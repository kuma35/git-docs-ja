promisor.quiet::
	true に設定すると、 部分クローン(partial clone)の追加オブジェクトを取得(fetch)するときに `--quiet` とみなします。

promisor.advertise::
	"true" に設定すると、 サーバーは使用しているプロミサー・リモートがある場合、プロミサー・リモート機能(promisor-remote capability)(linkgit:gitprotocol-v2[5] 参照)を使用してそれらを広告(advertise)します。 デフォルトは "false" で、 プロミサー・リモート機能は広告されません。

promisor.sendFields::
	追加のリモート関連フィールド名の、 カンマまたは空白で区切られたリストです。 サーバーは、 プロミサー・リモート機能を使用してプロミサー・リモート広告する際に、 このリストに含まれるフィールド名とそれに関連する設定値を送信します(linkgit:gitprotocol-v2[5] 参照)。 現在サポートされているフィールド名は "partialCloneFilter" と "token" のみです。
+
--
`partialCloneFilter`::: そのリモートの部分クローン・フィルタ(partial clone filter)を含みます。
`token`::: そのリモートの認証トークン(authentication token)を含みます。
--
+
フィールド名がこのリストに含まれ、 サーバー上で対応する `remote.foo.<field-name>` 構成変数が空で無い値に設定されている場合、 プロミサー・リモートの "foo" を広告する際にそのフィールド名と値が送信されます。
+
このリストは、 `promisor.advertise` 構成変数が "true" に設定されていない限り効果がありません。 また、 "name" と "url" フィールドはこの設定に関係なく常に広告されます。

promisor.acceptFromServer::
	"all" に設定すると、 クライアントはサーバーがプロミサー・リモート機能を使用して広告する、 全てのプロミサー・リモートを受け入れます。 "knownName" に設定すると、 クライアントはすでにクライアント側で設定されており、 サーバーが広告するものと同じ名前を持つプロミサー・リモートのみを受け入れます。 これはあまり安全ではなく、 サーバーとクライアントが名前と URL を切り替えない、 信頼できる企業環境などで使用可能です。 "knownUrl" に設定すると、 クライアントは名前と URL の両方がクライアント側で設定されているものと完全に一致するプロミサー・リモートのみを受け入れます。 これは "all" や "knownName" よりも安全なので、 可能であればこちらを使用すべきです。 デフォルトは "none" で、サーバーが広告するプロミサー・リモートは一切受け入れられません。 プロミサー・リモートを受け入れることで、 クライアントはサーバーが "fetch" や "clone" リクエストに対する応答から、 このプロミサー・リモートより遅延取得可能なオブジェクトを省略する可能性があることに同意します。 名前と URL の比較は英大文字小文字を区別します(case sensitive)。 linkgit:gitprotocol-v2[5] を参照してください。

promisor.checkFields::
	追加のリモート関連フィールド名の、 カンマまたは空白で区切られたリストです。 クライアントは、サーバーから送信されたこれらのフィールドの値が、 クライアント自身の設定の値と一致するかを、 プロミサー・リモートを受け入れる前にチェックします。 現在サポートされているフィールド名は "partialCloneFilter" と "token" のみです。
+
広告されたプロミサー・リモート(例: "foo")に対してこれらのフィールド名(例: "token")のチェックを行う場合、 特定のフィールドのチェックがパスするには以下の 3 つの条件をすべて満たす必要があります:
+
--
1. 対応するローカル設定(例: `remote.foo.token`)が設定されていること。
2. サーバーが、 リモート "foo" に対して "token" フィールドを広告していること。
3. ローカルで設定された `remote.foo.token` の値が、サーバーが "token" フィールドで広告した値と完全に一致すること。
--   
+
`promisor.checkFields` にリストされた任意のフィールド名についてこれらの条件のいずれかが満たされない場合、 広告された、 リモート "foo" は拒否されます。
+
"partialCloneFilter" フィールドについては、 これによりクライアントはサーバーのフィルタがローカルで期待されるものと一致することを保証でき、 フィルタリング動作の不整合を防げます。 "token" フィールドについては、 認証クレデンシャルが期待される値と一致することを検証するために使用できます。
+
フィールド値の比較は英大文字小文字を区別します(case-sensitively)。
+
"name" と "url" フィールドは、 この設定とは独立に `promisor.acceptFromServer` のポリシーに従って常にチェックされます。
+
フィールド名と値は、 `promisor.sendFields` 構成変数を使用してサーバー側でプロミサー・リモート機能経由で渡されるべきです。 これらのフィールドは、 `promisor.acceptFromServer` 設定変数が "none" に設定されてい無い場合にのみチェックされます。 "none" に設定されている場合、 この構成変数は効果がありません。 linkgit:gitprotocol-v2[5] を参照してください。
