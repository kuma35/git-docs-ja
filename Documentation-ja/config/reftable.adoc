reftable.blockSize::
	ブロックを書き込むときに reftable バックエンドによって使用されるバイト単位のサイズ。 ブロック・サイズは書込器(writer)によって決定され、 2 の累乗である必要はありません。 参照は複数のブロックにまたがることはできないため、 ブロック・サイズはリポジトリで使用される最長の参照名またはログ・エントリより大きくなければなりません。
+
仮想メモリ・システムまたはファイル・システムに優しい 2 のべき乗(4kB や 8kB など)が推奨されます。 サイズがより大きく(64kB)なると、 圧縮率が向上しますが、アクセス中に読取器(reader)にかかるコストが増加する可能性があります。
+
最大ブロック・サイズは 16777215 バイト(15.99 MiB)です。 デフォルト値は 4096 バイト(4kB)です。 値「0」を指定した場合はデフォルト値を使用します。

reftable.restartInterval::
	再開ポイントを作成する間隔。 ファイル作成時の再開ポイントは reftable バックエンドが決めます。 小さいブロック・サイズ(4k または 8k)には 16 ごと、 大きいブロック・サイズ(64k)には 64 ごとが好ましいです。
+
再開ポイントをより頻繁に作るようにすると、 プレフィックスの圧縮が減り、 再開テーブル(restart table)によって消費されるスペースが増加します。 その両方によりファイル・サイズが増加します。
+
再開ポイントの頻度が減ると、 プレフィックス圧縮がより効果的になり、 全体のファイル・サイズが現象しますが、 二分検索ステップの後に多くのレコードを閲覧する読取器(readers)では不利益が増加します。
+
1ブロックあたり最大 65535 の再スタート点がサポートされています。
+
デフォルト値では、 16 レコードごとに再スタート点が作成されます。 値「0」を設定した場合、 デフォルト値を使用します。

reftable.indexObjects::
	reftable バックエンドがオブジェクト・ブロックを書き込むかどうか。 オブジェクト・ブロックは、 オブジェクト ID を、 それらを指す参照に逆マッピングしたものです。
+
デフォルト値は `true` です。

reftable.geometricFactor::
	reftable バックエンドが新しいテーブルをスタックに追加するたびに、 自動圧縮を実行してテーブルが少量になるようにします。 バックエンドは、 テーブルが各テーブルのそれぞれのサイズに関して等比数列(geometric sequence)を形成することを保証することによってこれを行います。
+
デフォルトでは、 等比数列は係数 2 を使用します。 これは、 どのテーブルでも、 次に大きいテーブルは少なくとも 2 倍の大きさでなければならないことを意味します。 係数は最大 256 がサポートされています。

reftable.lockTimeout::
	reftable バックエンドが新しいテーブルをスタックに追加するときは常に、 中央の `tables.list` ファイルを更新する前にロックする必要があります。 この構成は、 別のプロセスがすでにロックを取得している場合に、 プロセスがロックを取得するまで待機する時間を制御します。 値 0 は、 まったく再試行しないことを意味します。 -1 は無期限に試行することを意味します。 デフォルトは 100(つまり、100 ミリ秒再試行)です。
