git-request-pull(1)
===================

NAME
----
git-request-pull - プルリクエスト文面生成(Generates a summary of pending changes)

SYNOPSIS
--------
[synopsis]
'git request-pull' [-p] <start> <URL> [<end>]

DESCRIPTION
-----------

上流(upstream)プロジェクトに対して、 上流プロジェクトのツリーに変更を取り込むよう依頼するリクエストを生成します。 このリクエストは標準出力に表示され、 ブランチの説明から始まり、 変更の概要をまとめ、 どこから変更を取り込めるかを示します。

上流プロジェクトには `<start>` という名前のコミットがあると予想され、出力では、そのコミット以降に行った変更を `<URL>` という名前のリポジトリーの、`<end>` という名前のコミットまで統合するように求められます。


OPTIONS
-------
`-p`::
	出力にパッチテキストを含めます。

<start>::
	開始コミット。これは、すでに上流の履歴に存在するコミットを指定します。

<URL>::
	プル元のリポジトリURL。

<end>::
	終了コミット(省略時デフォルトはHEAD)。プルを要求している履歴の先端にあるコミットを指定します。
+
`<URL>` で指定されたリポジトリの、ローカルにあるrefとは異なるrefの先端にコミットがある場合、「ローカル名 コロン(:) リモート名」である、 `<local>:<remote>` 構文を使用することができます。


EXAMPLES
--------

あなたが master ブランチで v1.0 リリースを基盤に作業を進め、 その変更をプロジェクトに統合したいとします。 まずは、 その変更を公開リポジトリーにプッシュして、 他の人に見えるようにします:

	git push https://git.ko.xz/project master

それから、あなたは以下のコマンドを実行します:

	git request-pull v1.0 https://git.ko.xz/project master

これにより、上流へのリクエストが生成され、 `v1.0` リリースと `master` の間の変更が要約されて、公開リポジトリーからプルされます。

ローカルにあるブランチとは名前が異なるブランチに変更をプッシュする場合、例えば、

	git push https://git.ko.xz/project master:for-linus

それからあなたはそれをプルするように頼むことができます

	git request-pull v1.0 https://git.ko.xz/project master:for-linus
